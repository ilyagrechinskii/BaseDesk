# Локальная разработка

## Что подготовлено сейчас

Подготовлены архитектурные документы, каталоги рабочих областей и синтетический JSON для mock-экранов. Новые Electron, Web API, EF Core, PostgreSQL и Docker Compose пока не реализованы. Не пытайтесь запускать новый стек командами старого прототипа.

1. Прочитайте [архитектуру](architecture.md), [правила веток](team-workflow.md) и README своей области.
2. Работайте в своей постоянной именной ветке; чужие файлы меняйте после согласования.
3. Авторы экранов начинают на mock-данных, Наталья — общие компоненты и CSS, Александр — Electron, Андрей — API. Готовности остальных приложений ждать не нужно.
4. Перед интеграцией согласуйте [DTO и маршруты](api-contracts.md), сигнатуры монтирования и общий Sidebar.

## Автономный frontend

Для HTML/CSS/JS нужен браузер и статический HTTP-сервер, без Node.js API в страницах. Если установлен Python 3, из корня репозитория можно выполнить:

```powershell
py -m http.server 8080 --bind 127.0.0.1
```

Python — только необязательный инструмент просмотра, не зависимость продукта. Можно использовать другой статический сервер, обслуживающий тот же корень и доступный только локально. Сервер останавливается `Ctrl+C`.

После реализации автором страницы откройте `http://localhost:8080/src/frontend/pages/home/`, `clients/` или `tasks/`. Сейчас в этих каталогах README, а не готовые HTML-страницы. Общий mock JSON доступен по `/docs/examples/mock-data.json`: массивы `clients`, `tasks`, `sections` и объект `organization`. Это общий набор данных для preview; реальные API-списки будут обёрнуты в `items`.

`index.html` экрана подключает будущий `preview.js` как модуль. Preview получает данные и вызывает экспорт страницы; основное приложение позднее вызывает тот же экспорт со своим источником данных. Проверяйте консоль, относительные пути, отсутствие зависимости от API и поведение с пустыми массивами. Общий Sidebar не блокирует автономную проверку контента.

## Backend и Electron

Андрей создаёт отдельный API-проект под .NET 10, выбирает совместимые версии EF Core и провайдера PostgreSQL, описывает восстановление зависимостей и запуск после реализации. Проверяет API через HTTP независимо от Electron. Существующие solution и global.json пока относятся к прототипу; до обновления проверяется доступность выбранного SDK.

Александр выбирает и фиксирует версию Electron/Node.js в собственной задаче, создаёт проект `desktop/`, затем добавляет команды запуска и адрес API в документацию. В корне сейчас нет нового `package.json`; команда `npm install` в корне не является способом подготовки новой архитектуры.

Следующим этапом команда добавляет Docker Compose для API и PostgreSQL, миграции и точные инструкции первого запуска. Пароли, строки подключения и `.env` остаются локальными; в репозиторий допустим только шаблон `.env.example` с фиктивными значениями. `.gitignore` уже исключает локальные конфигурации, сборки и логи. Не записывайте секреты в отслеживаемые JSON: ignore не защищает уже отслеживаемые файлы.

## Переходный период

[running.md](running.md) — историческая инструкция Electron.NET-прототипа, не нового стека. Старые файлы сохранены, чтобы не смешивать архитектурную задачу с миграцией. ## Проверка перед PR

Для этой задачи достаточно проверить ссылки документов, корректность JSON, наличие каталогов, отсутствие изменений кода прототипа и пользовательского SVG. Сборка старого приложения не подтверждает новую архитектуру. Правила PR: [pull-request-review.md](pull-request-review.md); план коммитов Issue #1: [commit-plan.md](commit-plan.md).
