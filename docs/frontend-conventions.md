# Организация frontend

Используем HTML, CSS и обычный JavaScript. React, Vue, Angular и TypeScript в этот этап не входят. Источник внешнего вида — уже утверждённые изображения экранов BaseDesk. Новый дизайн и работа в Figma не требуются. Если референс отсутствует локально, запросите утверждённое изображение у Ильи; не заменяйте его собственным дизайном.

| Область | Владелец | Содержимое |
| --- | --- | --- |
| `src/frontend/pages/home/` | Никита | Главный экран |
| `src/frontend/pages/clients/` | Дмитрий | Таблица клиентов |
| `src/frontend/pages/tasks/` | Артём | Таблица задач |
| `src/frontend/components/` | Наталья | Общие элементы, включая Sidebar |
| `src/frontend/styles/` | Наталья | Общие переменные, типографика, общие стили |
| `desktop/` | Александр | Electron и интеграция экранов |
| `src/backend/` | Андрей | API и работа с данными |

Работа над архитектурными документами и согласование изменений на границах областей — Илья. Изменять файлы другого владельца можно после согласования с ним в Issue или PR. Общий Sidebar реализуется один раз в `components/`; авторы страниц не копируют его разметку в каждый раздел.

## Первая неделя

Каждый экран самостоятельно работает на mock-данных без API, Electron и БД. Начальные данные и DTO описаны в [моделях](domain-models.md), общий пример лежит в [examples/mock-data.json](examples/mock-data.json). Изменение mock-данных в памяти страницы допустимо; это не сохранение на сервере. Для автономного просмотра не требуется сначала завершить Sidebar или оболочку.

В своей папке автор создаёт `index.html`, `page.css`, `page.js` и дополняет README инструкцией просмотра. Это будущие файлы реализации; сейчас подготовлены только README. Статический HTTP-сервер должен обслуживать корень репозитория, чтобы относительные ссылки на общие ресурсы работали одинаково у всех. Пример адреса: `http://localhost:8080/src/frontend/pages/clients/`. `file://` не является основным способом просмотра: загрузка JSON и ES-модулей требует HTTP. Команда сервера описана в [development.md](development.md).

## Предлагаемый интерфейс интеграции

До реализации Александр и авторы экранов подтверждают следующий контракт в Issue #1:

- `page.js` — ES-модуль с именованным экспортом `mountHomePage(root, { data })`, `mountClientsPage(root, { data })` или `mountTasksPage(root, { data })`;
- `root` — DOM-элемент области контента, `data` — объект mock-данных из общей схемы; позже оболочка получает тот же DTO через API;
- функция монтирования возвращает функцию очистки, которая снимает обработчики и освобождает ресурсы;
- отдельный `preview.js` загружает mock-данные и вызывает экспорт для автономного `index.html`; импорт `page.js` сам по себе не монтирует страницу;
- оболочка создаёт общий Sidebar один раз и при переходах размонтирует предыдущий экран; страница управляет только переданным `root`;
- страницы не импортируют Electron и не используют Node.js API; универсальный модуль запроса данных и обработку ошибок согласуют позднее.

Эта договорённость позволяет разрабатывать страницы отдельно и затем подключать их без копирования HTML и Sidebar. До её подтверждения возможны изменения сигнатур; не считайте её уже реализованным маршрутизатором. Подключение реального API — следующий этап после согласования с Андреем.

Правила имён, DOM и CSS: [frontend-coding-rules.md](frontend-coding-rules.md).
