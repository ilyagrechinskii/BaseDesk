# Запуск BaseDesk

> Историческая инструкция Electron.NET-прототипа из `legacy/electron-net`. Она не описывает новый стек. Текущий порядок разработки: [development.md](development.md), переход: [architecture.md](architecture.md). Старые команды ниже сохранены для справки.

Инструкция для текущего каркаса: окно Electron.NET, стартовая страница и проверка соединения с backend. Бизнес-функции пока не реализованы.

## Требования

- Windows 10/11 x64.
- .NET 10 SDK x64 — именно SDK, а не только Runtime.
- Node.js версии 22.12 или новее с npm.

Первый запуск требует интернета для загрузки NuGet-пакетов и Electron. Отдельно устанавливать ElectronNET.CLI и запускать `electronize start` не нужно: проект использует ElectronNET.Core.

## Запуск из VS Code

1. Откройте папку BaseDesk через «Файл → Открыть папку».
2. Откройте «Терминал → Создать терминал». Выберите PowerShell.
3. Убедитесь, что терминал находится в корне репозитория, где лежат `BaseDesk.sln` и `global.json`.
4. При первом запуске восстановите зависимости:

   ```powershell
   & 'C:\Program Files\dotnet\dotnet.exe' restore
   ```

5. Запустите приложение:

   ```powershell
   & 'C:\Program Files\dotnet\dotnet.exe' run --project src/backend/BaseDesk.App --launch-profile Desktop
   ```

Полный путь выбирает x64-версию .NET. Это полезно, если обычная команда `dotnet` находит версию из `C:\Program Files (x86)`, в которой нет SDK. Если SDK установлен в другом месте, используйте путь к его `dotnet.exe`.

Откроется отдельное окно BaseDesk. На странице должен появиться текст «Backend доступен. Приложение готово к разработке». Кнопка «Проверить соединение» повторяет запрос к backend.

Оставьте терминал работающим. Для остановки закройте окно приложения или нажмите `Ctrl+C` в терминале.

При следующих запусках достаточно команды `run`: она выполняет необходимую сборку и восстановление зависимостей.

## Короткие команды

Если обычная команда `dotnet` уже находит SDK x64, можно запускать из корня репозитория так:

```powershell
dotnet restore
dotnet run --project src/backend/BaseDesk.App --launch-profile Desktop
```

Проверить окружение можно командами:

```powershell
dotnet --info
node --version
npm --version
```

В выводе `dotnet --info` должен быть SDK версии 10.0.x и архитектура x64.

## Запуск в браузере

Профиль `Web` запускает backend без desktop-окна:

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' run --project src/backend/BaseDesk.App --launch-profile Web
```

Откройте:

- страницу приложения: <http://localhost:5120>;
- проверку backend: <http://localhost:5120/api/health>.

Ожидаемый ответ API:

```json
{"application":"BaseDesk","status":"ok"}
```

Обычная сборка для этого профиля всё равно подготавливает компоненты Electron. Для остановки нажмите `Ctrl+C`.

## Запуск в Visual Studio

1. Используйте Visual Studio с поддержкой .NET 10, например Visual Studio 2026.
2. Откройте `BaseDesk.sln`.
3. Выберите проект `BaseDesk.App` как запускаемый и профиль `Desktop`.
4. Нажмите `F5`.

## После изменения frontend

Редактируйте файлы в `src/frontend`, а не копии в `bin`. При сборке HTML, CSS и JavaScript копируются в выходной каталог `wwwroot`.

После правок остановите приложение и повторите команду `run` без `--no-build`, чтобы обновить эти копии.

## Типичные проблемы

- **Не найден SDK:** используйте полный x64-путь выше. Команда `& 'C:\Program Files\dotnet\dotnet.exe' --list-sdks` должна показывать SDK 10.0.x; если он отсутствует, установите .NET 10 SDK x64.
- **Не найдены Node.js или npm:** установите Node.js с npm и перезапустите терминал VS Code.
- **Ошибка загрузки NuGet или Electron:** проверьте интернет и повторите восстановление зависимостей и запуск. Не запускайте `npm install` в корне репозитория: зависимостями Electron управляет .NET-сборка.
- **Порт 5120 занят при запуске Web:** остановите ранее запущенную копию BaseDesk. Не завершайте неизвестные процессы только ради освобождения порта.
- **Нет соединения с backend:** посмотрите ошибки в терминале. В режиме Web проверьте ответ `/api/health` по адресу выше.

## Предупреждение о зависимости

При первоначальной проверке npm сообщил об уязвимости пакета `image-size`, который поставляется внутри Electron.NET. В текущем каркасе нет загрузки пользовательских изображений. Перед распространением приложения нужно проверить обновления Electron.NET и повторить аудит зависимостей.

Не применяйте `npm audit fix --force` к сборочному каталогу: его содержимое создаётся заново при сборке.
