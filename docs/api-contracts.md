# Предварительные HTTP API-контракты

**Согласовать с Андреем до реализации API.** Endpoints в этой задаче не реализованы. Поля, ограничения и семантика обновлений определены в [domain-models.md](domain-models.md); полные ответы сущностей доступны в [examples/mock-data.json](examples/mock-data.json).

## Общие правила

Базовый URL задаётся конфигурацией клиента. Тела запросов и ответы — JSON (`application/json`), кроме ответов 204 без тела. Идентификаторы в URL — UUID. POST возвращает 201, созданную сущность и `Location`; GET и обновления — 200 и сущность; DELETE — 204. GET списков возвращает объект `items`, пустой список — `{"items":[]}`. Пагинация, поиск и сортировка на сервере пока не входят в договорённость; mock-экраны работают с небольшими списками.

Ошибки: 400 — неверный формат/валидация, 404 — организация или ресурс не найдены, 409 — конфликт связи или состояния. Для неверного UUID предлагается 400. GET списка для отсутствующей организации возвращает 404, а не пустой список. При DELETE неизвестного ресурса — 404.

Предлагаемый формат ошибки (`application/problem+json`):

```json
{
  "type": "about:blank",
  "title": "Validation failed",
  "status": 400,
  "detail": "Проверьте указанные поля.",
  "errors": { "name": ["Название обязательно."] }
}
```

`errors` используется для ошибок полей, в остальных случаях может отсутствовать. Не возвращать строки подключения, SQL и стек исключений. Авторизация, роли, сотрудники и удалённая синхронизация здесь не определяются. Отсутствие авторизации ограничивает версию локальной разработкой; публичный сервер требует отдельной задачи.

## Маршруты

| Метод | Путь | Вход | Успешный ответ |
| --- | --- | --- | --- |
| GET | `/api/health` | Без тела | 200: health |
| POST | `/api/organizations` | Создание Organization | 201: Organization |
| GET | `/api/organizations/{id}` | Без тела | 200: Organization |
| PATCH | `/api/organizations/{id}` | Переданные изменяемые поля | 200: Organization |
| GET | `/api/organizations/{id}/sections` | Без тела | 200: `{ "items": [Section] }` |
| PUT | `/api/organizations/{id}/sections` | `{ "items": [SectionUpdate] }` | 200: `{ "items": [Section] }` |
| GET | `/api/organizations/{id}/clients` | Без тела | 200: `{ "items": [Client] }` |
| POST | `/api/organizations/{id}/clients` | Создание Client | 201: Client |
| GET | `/api/clients/{id}` | Без тела | 200: Client |
| PUT | `/api/clients/{id}` | Полный набор изменяемых полей Client | 200: Client |
| DELETE | `/api/clients/{id}` | Без тела | 204, либо 409 при связанных задачах |
| GET | `/api/organizations/{id}/tasks` | Без тела | 200: `{ "items": [Task] }` |
| POST | `/api/organizations/{id}/tasks` | Создание Task | 201: Task |
| GET | `/api/tasks/{id}` | Без тела | 200: Task |
| PUT | `/api/tasks/{id}` | Полный набор изменяемых полей Task | 200: Task |
| DELETE | `/api/tasks/{id}` | Без тела | 204 |

## Health и организация

`GET /api/health` → 200, подтверждает работу процесса API, а не готовность БД:

```json
{ "application": "BaseDesk", "status": "ok" }
```

`POST /api/organizations`:

```json
{ "name": "Демо-компания" }
```

Ответ 201 (GET возвращает ту же форму):

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "name": "Демо-компания",
  "createdAt": "2026-10-26T09:00:00Z",
  "updatedAt": "2026-10-26T09:00:00Z"
}
```

`PATCH /api/organizations/11111111-1111-4111-8111-111111111111` с телом `{"name":"Новое название"}` → 200 с полной Organization, новым `name` и обновлённым `updatedAt`. Идентификатор и `createdAt` сохраняются. Создание организации также создаёт три стандартных раздела.

## Разделы

PUT `/api/organizations/11111111-1111-4111-8111-111111111111/sections` атомарно заменяет настройки всех трёх существующих разделов. Это не создание или удаление типов разделов. Требуются все три элемента, без дубликатов ID и позиции; порядок задаётся `position`. `key` и `organizationId` берутся из существующих записей, в запрос не входят.

```json
{
  "items": [
    { "id": "22222222-2222-4222-8222-222222222221", "title": "Главная", "position": 0, "enabled": true },
    { "id": "22222222-2222-4222-8222-222222222222", "title": "Клиенты", "position": 1, "enabled": true },
    { "id": "22222222-2222-4222-8222-222222222223", "title": "Задачи", "position": 2, "enabled": true }
  ]
}
```

Ответ PUT и GET — `{"items":[...]}` с полными Section: каждый элемент содержит также `organizationId` и `key`. Точный пример — массив `sections` общего mock-файла, обёрнутый в `items`. Отключение раздела скрывает навигацию, но не удаляет клиентов или задачи.

## Клиенты

POST `/api/organizations/11111111-1111-4111-8111-111111111111/clients` и PUT `/api/clients/33333333-3333-4333-8333-333333333333` используют следующий полный набор изменяемых полей:

```json
{ "name": "Демо-клиент", "email": "client@example.com", "phone": null, "notes": "Пример для разработки" }
```

POST → 201; PUT → 200. Ответ содержит полную сущность:

```json
{
  "id": "33333333-3333-4333-8333-333333333333",
  "organizationId": "11111111-1111-4111-8111-111111111111",
  "name": "Демо-клиент", "email": "client@example.com", "phone": null,
  "notes": "Пример для разработки",
  "createdAt": "2026-10-26T09:00:00Z", "updatedAt": "2026-10-26T09:00:00Z"
}
```

GET клиента возвращает эту форму, список — `{"items":[<полная сущность>]}`. DELETE без связанных задач → 204 без тела. Если клиент используется задачей → 409 в общем формате ошибки, `title: "Client has linked tasks"`; автоматического удаления задач нет.

## Задачи

POST `/api/organizations/11111111-1111-4111-8111-111111111111/tasks` и PUT `/api/tasks/44444444-4444-4444-8444-444444444444`:

```json
{
  "clientId": "33333333-3333-4333-8333-333333333333",
  "title": "Связаться с клиентом", "description": null,
  "status": "todo", "dueDate": "2026-11-01"
}
```

Ответ POST → 201, PUT и GET → 200:

```json
{
  "id": "44444444-4444-4444-8444-444444444444",
  "organizationId": "11111111-1111-4111-8111-111111111111",
  "clientId": "33333333-3333-4333-8333-333333333333",
  "title": "Связаться с клиентом", "description": null,
  "status": "todo", "dueDate": "2026-11-01",
  "createdAt": "2026-10-26T09:00:00Z", "updatedAt": "2026-10-26T09:00:00Z"
}
```

GET списка — `{"items":[<полная сущность>]}`. DELETE → 204 без тела. Несуществующий или принадлежащий другой организации `clientId` в теле → 400 с ошибкой поля, без создания задачи. Клиент без связи задаётся как `null`.
