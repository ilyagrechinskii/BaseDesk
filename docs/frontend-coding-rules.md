# Правила HTML, CSS и JavaScript

Документ дополняет [соглашения frontend](frontend-conventions.md). Общие изменения согласуются с владельцами областей до реализации.

## Имена и область действия

- Каталоги, HTML/CSS/JS-файлы — `kebab-case`; точки входа экрана — `index.html`, `page.css`, `page.js`, `preview.js`.
- Переменные и функции JS — `camelCase`, константы конфигурации — `UPPER_SNAKE_CASE`. Экспорты страниц: `mountHomePage`, `mountClientsPage`, `mountTasksPage`.
- JavaScript подключается как ES-модули (`type="module"`). Не записывать состояние и функции в `window`; не использовать inline-обработчики `onclick`.
- CSS страницы ограничивается корневым классом `.home-page`, `.clients-page` или `.tasks-page`; дочерние классы имеют соответствующий префикс, например `.clients-page__table`.
- Стили компонента ограничиваются его собственным классом, например `.sidebar`. CSS-переменные общего оформления имеют префикс `--bd-` и определяются Натальей в `styles/`.
- Страница не меняет глобально `body`, `button`, `table` и другие общие селекторы. Базовые правила и reset принадлежат `styles/`.

## Поведение и данные

DOM ищется внутри переданного `root`, обработчики подключаются через `addEventListener` и снимаются при размонтировании. Повторное открытие экрана не должно создавать дублированные обработчики. Пользовательский текст выводится через `textContent`; не вставлять значения полей в `innerHTML`.

Не смешивать форматирование и данные: даты DTO сохраняются в ISO-формате, форматируются для отображения отдельно. Пустая дата — `null`, а не пустая строка. Проверка формы на frontend помогает пользователю, но не заменяет проверку API.

Каждый экран предусматривает заполненное и пустое состояние. Состояния загрузки и ошибки понадобятся при интеграции API; на mock-этапе можно описать их в README и проверить искусственно. Элементы управления должны иметь понятные подписи, формы — связанные `label`, таблицы — заголовки. Проверить управление клавиатурой.

До появления общего Sidebar оставлять область навигации пустой либо использовать автономный контент без неё. Не создавать временные копии общего компонента. Если общий CSS ещё не готов, использовать локальные стили в пределах корня страницы; перенос повторяющихся правил согласовать с Натальей.

В PR автор указывает способ автономного просмотра, использованный референс, проверенные состояния и изменения согласованных интерфейсов. Не подключать новые библиотеки и не менять файлы соседнего экрана без обсуждения.
