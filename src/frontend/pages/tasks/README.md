# Задачи — Артём

Постоянная ветка: `artem`. Рабочая область: эта папка. Табличное представление раздела «Задачи» по утверждённому изображению на mock-данных, независимо от API и Electron. Задача: [Issue #7](https://github.com/ilyagrechinskii/BaseDesk/issues/7).

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | Автономная страница просмотра, подключает `page.css` и `preview.js`. |
| `page.js` | ES-модуль с экспортом `mountTasksPage(root, { data })`; возвращает функцию очистки. Импорт сам по себе ничего не монтирует. |
| `page.css` | Стили экрана, ограниченные корнем `.tasks-page`. |
| `preview.js` | Загружает общий [mock-data.json](../../../../docs/examples/mock-data.json), добавляет демо-задачи и монтирует страницу. |

## Автономный просмотр

Из корня репозитория запустите статический сервер ([development.md](../../../../docs/development.md)):

```powershell
py -m http.server 8080 --bind 127.0.0.1
```

- заполненная таблица: `http://localhost:8080/src/frontend/pages/tasks/`
- пустое состояние: `http://localhost:8080/src/frontend/pages/tasks/?state=empty`

`file://` не используется: ES-модули и загрузка JSON требуют HTTP. Если общий JSON недоступен, preview пишет предупреждение в консоль и показывает только демо-задачи.

## Что реализовано

- заголовок «Задачи», подзаголовок, кнопка «Добавить»;
- таблица: «Название», «Исполнитель», «Приоритет», «Срок», «Статус», «Действия»; выбор строк и «выбрать все»;
- меню трёх точек: «Редактировать», «Изменить статус», «Удалить». Закрывается по Escape, клику вне меню и Tab; стрелки, Home и End перемещают фокус;
- пустое состояние: «Задач пока нет» и кнопка «Добавить задачу»; при поиске без результатов — «Ничего не найдено»;
- поиск по названию и исполнителю, пагинация по 8 строк — только в памяти страницы.

Даты DTO (`YYYY-MM-DD`) выводятся как `ДД.ММ.ГГГГ`; `null` в дате, исполнителе или приоритете отображается как «—». Значения выводятся через `textContent`.

## Чего пока нет (следующие этапы)

Kanban, календарь, «ИИ», уведомления и фильтры показаны как в изображении, но отключены. Модальных форм и CRUD нет: «Изменить статус» переключает статус по кругу (`todo` → `inProgress` → `done`), «Удалить» убирает задачу из памяти страницы. Ничего не сохраняется.

«Добавить», «Редактировать» и стрелка «Назад» только генерируют события на корне страницы (`bubbles: true`), на которые позже подпишется оболочка или модальная форма:

| Событие | `detail` |
| --- | --- |
| `tasks-page:add` | `{}` |
| `tasks-page:edit` | `{ taskId }` |
| `tasks-page:status-change` | `{ taskId, status }` |
| `tasks-page:delete` | `{ taskId }` |
| `tasks-page:back` | `{}` |

## Требует согласования

- **Поля DTO.** В [модели Task](../../../../docs/domain-models.md) нет исполнителя и приоритета, а на изображении они есть. Страница читает предлагаемые поля `assignee` (строка или `null`) и `priority` (`low`, `medium`, `high` или `null`). Демо-значения лежат в `preview.js`; общий `mock-data.json` не изменялся. Решение — с Андреем и Ильёй.
- **Общие стили.** Локальные переменные `--tasks-*` в `page.css` после появления токенов `--bd-*` переносятся в `styles/` по согласованию с Натальей.
- **Sidebar** не копируется; страница управляет только переданным `root`.
