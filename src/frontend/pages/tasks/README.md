# Задачи — Артём

Постоянная ветка: `artem`. Рабочая область: эта папка. Раздел «Задачи» на mock-данных, независимо от API и Electron: табличное представление по утверждённому изображению ([Issue #7](https://github.com/ilyagrechinskii/BaseDesk/issues/7)), затем модальные формы и Kanban, связанные с той же таблицей ([Issue #7](https://github.com/ilyagrechinskii/BaseDesk/issues/7), задача недели — формы и Kanban).

## Файлы

| Файл | Назначение |
| --- | --- |
| `index.html` | Автономная страница просмотра, подключает `page.css` и `preview.js`. |
| `page.js` | ES-модуль с экспортом `mountTasksPage(root, { data })`; возвращает функцию очистки. Импорт сам по себе ничего не монтирует. |
| `page.css` | Стили экрана, ограниченные корнем `.tasks-page`. |
| `preview.js` | Загружает общий [mock-data.json](../../../../docs/examples/mock-data.json), добавляет демо-задачи и монтирует страницу. |

## Автономный просмотр

Из корня репозитория запустите статический сервер ([development.md](../../../../docs/development.md)):

```powershell
py -m http.server 8080 --bind 127.0.0.1
```

- заполненная таблица: `http://localhost:8080/src/frontend/pages/tasks/`
- пустое состояние: `http://localhost:8080/src/frontend/pages/tasks/?state=empty`

`file://` не используется: ES-модули и загрузка JSON требуют HTTP. Если общий JSON недоступен, preview пишет предупреждение в консоль и показывает только демо-задачи.

## Что реализовано

- заголовок «Задачи», подзаголовок, кнопка «Добавить»;
- переключение «Таблица» / «Канбан» в тулбаре; оба представления читают и меняют один и тот же массив задач в памяти страницы — изменение в одном сразу видно в другом;
- таблица: «Название», «Исполнитель», «Приоритет», «Срок», «Статус», «Действия»; выбор строк и «выбрать все»; поиск по названию и исполнителю; пагинация по 8 строк;
- Kanban: три колонки — «К выполнению» (синяя), «В работе» (жёлтая), «Выполнено» (зелёная), счётчик задач в шапке каждой колонки, кнопка «Добавить задачу» в цвет колонки. Цвета колонок и бейджей статуса в таблице заданы одними и теми же CSS-переменными (`--tasks-status-*`), поэтому не могут разойтись;
- перетаскивание карточки между колонками Kanban (HTML5 Drag & Drop) меняет статус задачи; визуальная подсветка колонки под курсором при перетаскивании;
- меню трёх точек (общее для строки таблицы и карточки Kanban): «Просмотреть», «Редактировать», «Удалить». Закрывается по Escape, клику вне меню и Tab; стрелки, Home и End перемещают фокус;
- модальное окно добавления/редактирования задачи (`<dialog>`): поля «Название» (обязательное, с валидацией), «Исполнитель», «Приоритет», «Статус», «Срок», «Описание»; открывается по кнопке «Добавить» в шапке, «Добавить задачу» в пустом состоянии и колонках Kanban, а также через меню «Редактировать»;
- модальное окно просмотра задачи: все поля только для чтения, кнопка «Редактировать» переоткрывает ту же форму в режиме редактирования;
- модальное окно подтверждения удаления с названием задачи; подтверждение убирает задачу из общего массива и перерисовывает оба представления;
- пустое состояние таблицы: «Задач пока нет» и кнопка «Добавить задачу»; при поиске без результатов — «Ничего не найдено» (аналогично в пустой колонке Kanban).

Даты DTO (`YYYY-MM-DD`) выводятся как `ДД.ММ.ГГГГ`; `null` в дате, исполнителе, приоритете или описании отображается как «—». Значения выводятся через `textContent`. Статус «Отменено» сознательно не добавлялся — вне рамок недельной задачи.

## Чего пока нет (следующие этапы)

Календарь, «ИИ», уведомления и фильтры показаны как в изображении, но отключены. CRUD не сохраняется — только в памяти вкладки; при перезагрузке страницы данные сбрасываются к демо-набору `preview.js`. Перетаскивание карточек не имеет клавиатурной альтернативы; сменить статус с клавиатуры можно через модальную форму редактирования (поле «Статус»). Меню колонки Kanban (три точки у заголовка, как на изображении) не реализовано — колонки статичны.

«Добавить», «Редактировать» (по сохранению), «Изменить статус» (по drag & drop) и «Удалить» (по подтверждению), а также стрелка «Назад», по-прежнему генерируют события на корне страницы (`bubbles: true`) — для будущей оболочки и аналитики; сама страница теперь не ждёт внешнего ответа и обрабатывает действие сразу через модальные окна:

| Событие | `detail` | Когда |
| --- | --- | --- |
| `tasks-page:add` | `{ taskId }` | после сохранения новой задачи в форме |
| `tasks-page:edit` | `{ taskId }` | после сохранения изменений в форме |
| `tasks-page:status-change` | `{ taskId, status }` | после перетаскивания карточки в другую колонку |
| `tasks-page:delete` | `{ taskId }` | после подтверждения удаления |
| `tasks-page:back` | `{}` | клик по стрелке «Назад» |

## Требует согласования

- **Поля DTO.** В [модели Task](../../../../docs/domain-models.md) нет исполнителя и приоритета, а на изображении они есть. Страница читает предлагаемые поля `assignee` (строка или `null`) и `priority` (`low`, `medium`, `high` или `null`). Демо-значения лежат в `preview.js`; общий `mock-data.json` не изменялся. Решение — с Андреем и Ильёй.
- **Общие стили.** Локальные переменные `--tasks-*` в `page.css` после появления токенов `--bd-*` переносятся в `styles/` по согласованию с Натальей.
- **Оформление модальных окон.** Утверждённого изображения для форм добавления/редактирования, просмотра и подтверждения удаления нет — вёрстка сделана в стиле уже утверждённой таблицы и Kanban (те же `--tasks-*` токены, радиусы, кнопки). Требует согласования с Натальей до переноса в общие стили.
- **Sidebar** не копируется; страница управляет только переданным `root`.
